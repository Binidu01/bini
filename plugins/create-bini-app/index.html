create-bini-app

Official

Official scaffolder for Bini.js. Creates a production-ready project with routing, API routes, native targets, and deployment tooling configured from the first commit.

Overview

create-bini-app is the official CLI that scaffolds a new Bini.js project. One command generates a complete, production-ready codebase - file-based routing, API routes, environment handling, native app wiring, and deployment tooling - configured correctly from the first commit.

Quick Start

The fastest way to scaffold a new Bini.js project:

>_Terminal
$ npx create-bini-app@latest my-app
$ cd my-app
$ npm run dev

On installation, you'll see the following prompts:

>_Terminal
◇
Project name?
my-bini-app
◇
Use TypeScript?
● Yes / ○ No
↑/↓ to navigate • Enter: confirm
◇
Styling solution?
● Tailwind CSS
○ CSS Modules
○ None
↑/↓ to navigate • Enter: confirm
◆
Platforms?
◼ Web
◻ Desktop (Windows, macOS, Linux)
◻ Android
◻ iOS
↑/↓ to navigate • Space: select • Enter: confirm

When a desktop or mobile target is picked, you're also asked for the app name and the bundle ID organization. iOS is only offered on macOS.

CLI flags

Skip prompts by passing flags directly:

FlagDescription
--typescript / --javascriptLanguage (create)
--tailwind / --css-modules / --noneStyling (create). Only one may be used
--platform <targets>web (default) · desktop · android · ios; comma-separated or repeated
--app-name [name]App name (default: project name in title case)
--org [domain]Bundle ID prefix as a reverse domain, e.g. com.acme (default com.bini)
--sign / --nosignAuto-confirm or skip code-signing setup
--npm / --pnpm / --yarn / --bunForce a package manager instead of auto-detecting
--no-installSkip installing dependencies
--no-gitSkip git init (create)
--forceDelete and overwrite an existing directory of the same name
--yes, -yNo prompts: accept the default for every unanswered question
--version, -v / --help, -hPrint version / show help

Requirements

  • Minimum Node.js version: 20.19.0
  • Operating systems: macOS, Windows, and Linux.
  • For desktop builds: Windows (C++ Build Tools), macOS (Xcode CLT), Linux (WebKitGTK).
  • For mobile builds: Android (JDK 17, Android Studio), iOS (Xcode, CocoaPods).

Commands

CommandDescription
create-bini-app [name]Create a new project (offers to add a platform when run inside one)
create-bini-app add [targets]Add desktop and/or mobile targets to an existing project
create-bini-app remove [targets]Remove desktop and/or mobile targets from the project
create-bini-app sign [targets]Set up or redo code signing
create-bini-app --app-name [name]Change the native app name (inside a project)
create-bini-app --org [domain]Change the bundle ID prefix (inside a project)
create-bini-app doctorCheck your machine for Tauri (runs tauri info)
create-bini-app cleanDelete build output (Vite and Tauri), keeps node_modules
create-bini-app upgradeUpdate dependencies and refresh template files

add, remove, sign, doctor, clean, and upgrade must be run inside a project.

Add or remove platforms

Use add to bring in desktop, Android, or iOS at any point without recreating the project - existing routes, styles, and configuration are never touched. Use remove to delete the generated platform folders and scripts for a target you no longer need.

Add a target

>_Terminal
$ npx create-bini-app@latest add
$ npx create-bini-app@latest add desktop android
$ npx create-bini-app@latest add ios --sign

With no target, the CLI shows a checklist of platforms that are not yet added:

>_Terminal
◇
Add platforms?
◼ Desktop (Windows, macOS, Linux)
◻ Android
◻ iOS
↑/↓ to navigate • Space: select • Enter: confirm
◇
App name?
Newapp
◇
Organization (bundle ID prefix)?
com.bini
◆
Set up windows signing now?
○ Yes / ● No
↑/↓ to navigate • Enter: confirm

The first native target adds the shared src-tauri/ setup, the Tauri packages, and every native script. Re-running is safe - anything already configured is skipped.

Remove a target

>_Terminal
$ npx create-bini-app@latest remove
$ npx create-bini-app@latest remove android
$ npx create-bini-app@latest remove desktop android ios

remove lists what it will delete and asks for confirmation. With no target, it shows a checklist of platforms that are present:

>_Terminal
◆
Remove platforms?
◼ Desktop (Windows, macOS, Linux)
◻ Android
◻ iOS
↑/↓ to navigate • Space: select • Enter: confirm

Web cannot be removed. Desktop shares src-tauri/ with mobile, so it can only be removed together with all of them.

Rename the app or change the bundle ID

The native app name and bundle identifier live in src-tauri/tauri.conf.json. Run one of these from inside the project to change them:

>_Terminal
$ npx create-bini-app@latest --app-name
$ npx create-bini-app@latest --org
$ npx create-bini-app@latest --app-name "My App" --org com.acme
>_Terminal
◇
New app name?
My App
◇
Bundle ID prefix (reverse domain)?
com.acme
◆
Changing the identifier makes stores treat this as a new app. Continue?
● Yes / ○ No
↑/↓ to navigate • Enter: confirm
  • --app-name updates productName and the window title.
  • --org rebuilds the identifier as <org>.<project>.
  • Generated Android and iOS projects keep their old values. Remove and re-add the platform to regenerate them, or edit them by hand.

Code Signing

Signing is offered when you add a native target, and can be set up or redone at any time with sign. Bring real credentials - self-signed certificates are not supported.

>_Terminal
$ npx create-bini-app@latest sign
$ npx create-bini-app@latest sign android

Values for GitHub Actions are saved to .env.signing and uploaded as secrets by npm run deploy. Local builds sign from your keychain, certificate store, and the git-ignored tauri.*.conf.json files. Add --ci-only to save only the CI values.

Maintenance commands

doctor

>_Terminal
$ npx create-bini-app@latest doctor

Runs tauri info to check Rust, the platform toolchains, and versions.

clean

>_Terminal
$ npx create-bini-app@latest clean

Deletes dist/, the generated native build folders, and the Rust build cache. node_modules is kept.

upgrade

>_Terminal
$ npx create-bini-app@latest upgrade

Updates dependencies and refreshes template files. src/, package.json, and vite.config.* are never overwritten.
